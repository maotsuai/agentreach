## 实际交付行为与边界

- PathMapper 区分受信入口的 Guest、Host 协议和 file URI 命名空间，单次 URI 解码，检查根分量、双路径、编码与长度；不重写 Shell 文本。Host 协议别名与 Guest 根严格双向分量嵌套返回 `path_denied`，相等与分量兄弟允许；检查 shared host_path 和每个原始/规范控制 cwd 别名。
- managed FileOps 强制使用 Guest `/usr/local/bin/reach-helper` 的 rooted 协议，固定项目根、记录摘要和根 inode 身份，覆盖 CLI、全部 exec-server 文件入口、copy、canonicalize、pool/reopen 与文件句柄。缺失或旧 helper 明确 `unsupported`，没有 POSIX/Python、Host 构建或自动安装兜底。
- 实际文件操作使用 Go 1.25.8 `os.Root`。写入使用根内父目录句柄、独占临时文件和原子 rename；多硬链接普通文件的内容读写默认拒绝；不能删除项目根。内容与 cwd 打开使用非阻塞方式，避免 FIFO 在类型检查前阻塞。
- 一次性 launcher 核对协商根身份，通过根句柄取得 cwd、持有目录 fd 后进入并 exec；后续不追加字符串 `cd`。物理 cwd 由固定 helper 经 base64 完整回传，Host 解码后验证再持久化。
- Guest Shell 运行期间仍可自行 `cd` 根外；该 cwd 不会持久化或写入 Host bookkeeping。managed cwd 明确拒绝 CR/LF，支持尾部空格；FileOps 文件名不受这一 cwd 限制。
- managed copy 明确不支持 symlink；合法根内目录 symlink 的 metadata、canonicalize 和受限 follow-walk 可用。遍历、搜索、文件内容和帧均有显式预算。
- project schema=1、固定 revision/generation=1 和 session schema v2 保持原契约。P0 guard 失败锁存和 unmanaged tier/协议保留。

这些是文件 API 与启动 cwd 约束，不是任意 Guest Shell 的 OS 文件系统沙箱，也不提供敌对同 UID Guest/Host 或已控制内核下的隔离保证。详见 [MANAGED-PROJECTS.md](../MANAGED-PROJECTS.md)。

## 审计修正与最终映射契约

独立审计的真实 rooted helper 写入复现曾得到 `intended="intended-old" unrelated="requested-new"`，Write 返回成功。根因是 exec-server 已将协议路径映为 Guest absolute，rootedOps 又按 Protocol 重映；原始证据保留在 `audit-B1-write_test.go`、`audit-B1-overlay.json`、`audit-B1-result.log`。
