## 已执行实验与反证

1. 原始 `remain-on-exit` + collector 实验：1,048,579 字节及 raw 输入逐字节一致，但 pane dead 后 pipe 仍打开，不能以输出暂时不增长认定 drain。
2. `remain-on-exit=off` 的 25 次快速退出均逐字节一致并收到 EOF。慢 collector 同样保留全部字节。单独最后一个 session 的 `pane-exited` hook 没有留下退出证据；不能只凭 EOF 区分正常结束与 server 故障。
3. `pane-died` hook 的隔离慢收集实验成功；真实 fixture raw 输入再次出现 dead pane、Python zombie、缺失状态/结束标记。该任务 server 的一次诊断 `SIGCHLD` 使退出证据和 EOF 完成，原始失败保留。没有把定时发信号作为产品补偿，也没有宣称已定位上游或内核根因。
4. 最终采用自然 pane 销毁 + 专用内部控制 pane 保留 `pane-exited` hook 上下文。hook 记录自然结束后关闭控制 pane；collector EOF、log fsync、最终 offset 落盘后才完整。隔离慢收集/快退出/raw 输入均通过；不依赖 Host 轮询或新增通用 PTY supervisor。
5. 公共 `hostpath.Canonical` 在目录锁创建竞态下把新出现的普通目录误报为 dangling path；现只拒绝真实 symlink，继续检查祖先。真实2000次目录 churn、10次hostpath/terminal race、全量检查/lint/三平台构建通过，未放宽链接边界。
6. raw PTY 下 load-buffer + paste-buffer `-r` 保留本次 NUL、Ctrl-C 字节、CR/LF、ANSI 粘贴边界和 `0xff`。这是 tmux/PTY 字节接缝证据，不保证任意应用的 line discipline 或二进制协议。

源码核对使用固定 [tmux 3.3a window.c](https://github.com/tmux/tmux/blob/3.3a/window.c)、[server-fn.c](https://github.com/tmux/tmux/blob/3.3a/server-fn.c)、[notify.c](https://github.com/tmux/tmux/blob/3.3a/notify.c)；真实实验结果优先于源码推断。最终自然退出路径不保证应用 exit code，缺失值不冒充 0。
