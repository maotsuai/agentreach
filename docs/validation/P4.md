## 已实现的行为

- ServiceSpec 闭合准入、独立严格状态、精确执行摘要；Host 默认 deny，P2 精确审批、durable intent/result 和 operation ID 保持权威。未知结果和重复请求不重新派发。
- sidecar 使用私有 Host 生成的 Compose，固定 CLI/plugin 指纹及 cwd/env/file；create 不 start → 完整配置检查 → exact-ID start → readiness。无仓库 Compose/.env/override/build/pull，不放松 P0 workspace 快照。
- workspace 服务复用 P3 的私有 service-backends 命名空间，公共 terminal 不能发现/控制，没有交互 service write。首次 stop、重复 stop、后续 inspect 均如实返回 descendants=unconfirmed。
- 生产 open_url 解析当前精确 exposure，审批后再次核验，只生成受限 loopback URL；跨项目、任意 origin、旧代次拒绝。
- 按需独立 Host manager，私有 socket/nonce、真实持有的 loopback listener、有界 TCP 双向与 half-close、授权撤销关闭已有连接；不凭 PID 文件杀进程。正常退出 cancel/join 所有观察和 worker，旧实例不重放。
- 请求及完整 MCP wire（包括二次 JSON 转义）不超过 64 KiB；Spec 16 KiB、日志 8 MiB/每读 16 KiB、32 services、16 fixed publications、16 retained dynamic exposures，无自动淘汰。预算失败保留可取得的原 resource/operation ID。
- 动态暴露和拨号前要求新 readiness；拨号后在首个 payload 前、以及已有连接监测时，仅重核完整 runtime/process/endpoint 身份，避免对等待该请求的单线程 HTTP 服务再次发送 health 请求。身份成功不更新历史 readiness；readiness 与身份各自有观察门控，身份成功不等待 app-health 持有的生命周期锁。
