## 真实 harness

Claude Code 2.1.220 的 SHA-256 为
`8addc857f3fe64d5a0368af9ee50321b50afb4a6918ba3ef018ab84f5dbbe081`，
Codex 0.148.0 的 SHA-256 为
`b0308517b20543012fa2171aa3d46ce455a7456c4eb2a552ab9468ba4eeb1e50`。
候选 10 使用真实固定 binary、临时隔离 HOME 和 localhost 脚本模型。未调用付费
模型。原始工具结果、HTTP 检查和操作日志位于 `evidence/harness-10`。

- 两种模式共八个 shell 和 native patch 用例通过，包括 Host canary 约束与根外写入拒绝。
- shared Claude 和 owned Codex 各两次完整进程启动，分别附着原终端并读到
  140、240。四个用例通过。
- 两种模式的 Claude 与 Codex 共四组 sidecar 流程通过。每组完成精确审批、
  Agent 退出后 HTTP 200、另一次启动查询日志、调用生产 open_url 以及批准停止。
  停止后发布不可访问，见八份阶段 `result.json`。
- 候选 11 的增量仅涉及受控 workspace provision 的快照和回执，复验范围为该
  生命周期、只读计划、全量 Guest 检查与候选构建。

## 独立审计与剩余边界

独立审计覆盖 47 个变更的 Go/Python 文件。按路径排序、以路径加 NUL、文件
SHA-256 加换行聚合，指纹为
`27300ca500328c6c54f10119abf320f9aa17a74c64fb91488f7efe3eaac74357`。
审计发现的审批时间窗、空 epoch 恢复、常驻 manager 和 P4 协议兼容、nonce、
provision 证书及 P2 回执权威问题已修正。审计还独立运行归档测试和额外
负例，并独立复核候选 11 的原生差异修正。原生演练由主会话执行及核对。

- 卷不可用与 daemon 不可达采用故障注入。未执行物理拔盘、系统睡眠唤醒、
  真实工作盘写满、全局 engine 重启/升级、或持锁进程的真实 SIGKILL。遗留
  锁按保留 inode 和证明原持有者已退出的操作流程处理。
- 原生执行环境是 macOS 和其 Linux Guest。Windows 仅构建；真实重启后的
  旧策略时钟 epoch 未演练。原有 ledger 在 boot identity 变化时拒绝授权。
- 外部 LAN 设备、强制 VPN 路由中断及 OrbStack Apply and Restart 后隔离仍
  属 P4 部署缺项。Guest IP 和域名旁路仍是单独网络边界。
- 隔离升级夹具上的旧 P4 workspace HTTP 代理曾超时，Guest 直连返回预期正文。
  换用 TCP readiness 后，迁移请求写入前曾收到 HTTP 200，写入后的一次 HTTP
  请求仍超时。旧进程跨请求和批准保留 TCP listener 已实测，这一期间的 HTTP
  连续性仍未验成。失败见 `native-audit-upgrade-10.log`、
  `native-audit-upgrade-http-probe-2.log` 和 `native-audit-upgrade-resumed-10.log`。
- Docker 与 Host 文件没有共同事务。已经派发的 Docker 动作可能跨发布完成。
  固定发布和 detached 后代保留各自生命周期。
